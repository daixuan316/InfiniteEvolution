# 单局无缝无限探索地图设计

> 日期：2026-11-08  
> 状态：设计已确认，待用户复核  
> 引擎：Cocos Creator 3.8.8 + Oops Framework  
> 目标平台：抖音小游戏

## 1. 目标

将当前固定 `42×24` 网格、约 `4032×2304` 世界单位的医院城区，扩展为可持续生成、无加载界面切换的无限探索世界。

系统必须满足：

- 玩家接近当前区域边缘前，后台确定性生成相邻区块。
- 玩家离开后回收远处场景节点，控制内存、节点数量和更新成本。
- 相同世界种子与区块坐标始终生成相同道路、建筑、地标和初始交互物。
- 区块回收或退出游戏后，只保存相对初始状态发生的变化；再次进入时可正确还原。
- 普通住宅构成城市主体，社区商业和小型工业节点提供节奏变化，医院等关键地标保持稀有。
- 新增资源沿用现有俯视像素末世工业风，不降低当前医院地图的视觉品质。

本设计是对 `docs/design/02-world-exploration.md` 中有限半开放地图规则的后续扩展。随机性仍受道路连通、内容配额、距离冷却和保底规则约束，不采用无法验证的完全随机拼接。

## 2. 已确认方案

采用“程序骨架＋模块化美术区块”：

1. 根据世界种子与永久区块坐标生成道路连接和街区主题。
2. 在道路骨架周围生成建筑槽、空地槽、事件槽和交互物槽。
3. 从模块化住宅、商业、工业、空地和稀有地标预制件中确定性选择资源。
4. 应用区块变化记录，再创建 Cocos 表现节点与战斗实体。
5. 玩家离开后回收表现节点，永久逻辑坐标和变化记录继续存在。

不采用纯程序绘制建筑，因为难以匹配当前美术品质；不采用整张手工地图随机拼接，因为资源量大、重复明显且道路接缝难以稳定验证。

## 3. 空间规格

### 3.1 区块尺寸

- 逻辑格尺寸继续使用 `96` 世界单位。
- 单区块为 `14×8` 逻辑格，即 `1344×768` 世界单位。
- 当前 `42×24` 地图可视为 `3×3` 个新规格区块，便于逐步迁移现有逻辑和素材。
- 永久区块键使用有符号整数坐标，例如 `12:-7`。
- 区块内稳定对象 ID 由 `chunkKey + localSlotId + typeId` 派生，不依赖加载顺序。

### 3.2 流送范围

- 玩家所在区块及周围 `3×3` 区块为活跃区：启用碰撞、交互、AI 和局部寻路。
- 外围扩展到 `5×5` 为预加载区：提前完成布局生成和资源准备，但不运行远处 AI。
- 超出预加载范围的区块进入休眠并回收节点、动画、碰撞体和临时实体。
- 区块加载和回收设置每帧预算，不能在跨边界的一帧内集中创建全部节点。

### 3.3 永久坐标与浮动原点

逻辑层保存永久区块坐标和区块内位置；表现层只使用相对当前浮动原点的本地坐标。玩家离当前渲染原点超过安全阈值时，整体平移活动世界节点，并更新原点偏移。

浮动原点不得改变：

- 区块键与随机结果。
- 存档中的玩家永久位置。
- 稳定对象 ID。
- 跨区块路线和已发现地标坐标。

## 4. 确定性生成

### 4.1 随机流

世界保存一个 `worldSeed`。不同用途使用独立派生随机流：

- 道路连接。
- 街区主题。
- 建筑和外观变体。
- 初始交互物。
- 初始敌群与事件。

某一系统增加随机抽取时，不能改变其他系统的既有结果。所有散列与伪随机算法需要固定实现和测试向量，不能使用 `Math.random()`。

### 4.2 道路骨架

每条区块边界连接由共享边键决定，确保两个相邻区块独立生成时对同一出口得出相同结果。生成器至少支持直路、弯道、十字、T 字、支路和死路，但必须满足：

- 每个区块至少一个有效出口。
- 活跃区域中的可玩道路连接到玩家当前连通分量。
- 不生成互相隔绝且无法进入的奖励或关键地标。
- 死路必须提供收益、事件或清晰的风险反馈，不能成为无意义长距离跑图。

### 4.3 建筑与内容比例

以建筑槽统计，长期目标比例为：

| 内容 | 目标比例或频率 |
|---|---:|
| 普通住宅、公寓、联排房 | 60–70% |
| 沿街商铺、车库、小仓库 | 20–30% |
| 公园、停车场、废墟、封闭庭院 | 5–12% |
| 社区公共设施 | 5–8% |
| 医院、警局、工厂、实验室等关键地标 | 平均每 20–35 个区块一个 |

比例允许受街区主题影响，但在批量样本中必须回归目标区间。

### 4.4 稀有地标

稀有地标不能依赖“先生成哪个区块”。每个区块先根据散列产生候选优先级，仅当它在最小距离邻域内胜出且满足主题条件时才生成地标，形成确定性的稀疏分布。

- 同类关键地标至少间隔 12 个区块。
- 地标可占用 2–4 个普通建筑槽，必要时跨越视觉区块，但其逻辑所有权归属于一个锚点区块。
- 已发现地标写入世界索引；其画面卸载后仍可用于地图标记和远距离目标规划。
- 关键任务地标不得只依赖低概率自然生成，任务系统可以预留一个满足距离约束的确定性目标。

## 5. 组件边界

### 5.1 纯逻辑组件

| 组件 | 职责 |
|---|---|
| `WorldSeed` | 固定散列、派生随机流和测试向量 |
| `ChunkCoordinate` | 永久坐标、区块内坐标和本地表现坐标转换 |
| `RoadGraphGenerator` | 共享边出口、道路骨架和入口门户 |
| `ChunkLayoutGenerator` | 建筑槽、主题、资源引用和初始对象定义 |
| `LandmarkGenerator` | 稀有地标候选竞争、距离冷却和任务预留 |
| `WorldDeltaStore` | 默认状态之外的区块变化与序列化 |
| `ChunkPortalGraph` | 已知区块入口图和跨区块路线 |

以上组件不引用 Cocos 节点，可在 Node 测试环境中批量生成和验证。

### 5.2 运行时组件

| 组件 | 职责 |
|---|---|
| `InfiniteWorldController` | 当前永久位置、流送范围、浮动原点和生命周期协调 |
| `ChunkStreamer` | 生成队列、预加载、激活、休眠、取消和每帧预算 |
| `ChunkView` | 将布局实例化为道路、建筑、装饰、碰撞和标记 |
| `ChunkObjectPool` | 回收建筑节点、装饰、交互物和常见敌人表现 |
| `ChunkNavigationRuntime` | 区块局部 A*、门户连接和动态阻挡更新 |

`BattleHUDViewComp` 不承担生成算法；它只消费当前活动世界、玩家位置、路线和地图快照。

## 6. 数据流

区块进入预加载范围时：

1. `ChunkStreamer` 根据玩家永久位置计算目标区块集合。
2. `ChunkLayoutGenerator` 使用 `worldSeed + chunkCoordinate` 生成纯数据布局。
3. `WorldDeltaStore` 将已开启、已摧毁、已发现和事件进度应用到布局。
4. 资源异步准备完成后，`ChunkView` 从对象池实例化表现。
5. 区块进入活跃范围后启用碰撞、交互、AI 和局部导航。

区块离开范围时：

1. 停止生成、AI、计时器和事件订阅。
2. 把相对默认状态发生的变化写入 `WorldDeltaStore`。
3. 归还表现节点和临时实体。
4. 丢弃可由种子重建的布局缓存，仅保留受容量限制的近期缓存。

## 7. 状态与存档

存档至少包含：

- 生成算法版本和 `worldSeed`。
- 玩家永久区块坐标与区块内位置。
- 已发现地标索引。
- 以区块键分组的稀疏变化记录。
- 需要持续的事件实例与任务预留地标。

变化记录只保存与默认生成结果不同的字段，例如：

- 容器已开启及其领取结果。
- 路障、门、设施或巢穴已摧毁、修复或切换。
- 一次性探索点已完成。
- 持续事件的阶段和截止时间。

普通环境装饰、道路、建筑初始选择和可重建的初始敌群不写入存档。保存加载后先用原算法重建默认区块，再应用变化记录。

生成算法变更必须提升 `generationVersion`。正式存档使用旧版本生成器重建旧世界，或通过明确迁移转换；不能静默用新算法改写已探索区域。

## 8. 寻路与移动

现有 `GridPathfinder` 的有限 `columns/rows` 网格不能直接扩展成无限数组。新导航分两层：

- 区块内继续使用小型网格 A*，网格尺寸固定且包含动态阻挡层。
- 跨区块使用入口门户图选择区块序列，再逐段请求局部路径。

点击目标、玩家直接移动、翻滚、敌人追击和小地图路线继续引用同一份最终通行数据。目标区块尚未激活时，只规划到已加载边界门户，并在新区块准备完成后续接路线。

## 9. 小地图与完整地图

- 小地图改为以玩家为中心的局部窗口，不再按固定 `worldWidth/worldHeight` 缩放整个世界。
- 完整地图显示已探索区块、已发现地标和当前目标；未探索无限区域使用战争迷雾。
- 地图缓存只保存简化道路与标记数据，不保留完整场景节点。
- 当前位置和地标使用永久坐标，浮动原点不影响地图显示。

## 10. 美术方向与资源

### 10.1 风格基线

沿用当前医院城区和灰港区域地图：

- 俯视像素美术与清晰方形建筑轮廓。
- 蓝灰混凝土和深色沥青为主体。
- 青色窗灯、能源管线作为科技强调色。
- 橙黄色管线、警示条和道路标线作为工业强调色。
- 绿色植被侵蚀与局部积水表达末世荒废。
- 洋红污染只用于危险区域和特殊设施，不能在普通住宅中过量使用。

所有文字、数值和交互提示继续由程序绘制，不烘焙进地图资源。

### 10.2 首批模块化资源

| 类别 | 首批内容 |
|---|---|
| 道路 | 直路、弯道、十字、T 字、支路、死路、停车入口、破损覆盖层 |
| 住宅 | 低层住宅 3 个主体、公寓 3 个主体、联排房 2 个主体 |
| 商业 | 便利店、药店、餐馆、修车铺、加油站、小超市 |
| 小型工业 | 小仓库、车库、维修院、材料堆场 |
| 填充地块 | 停车场、小公园、废墟、封闭庭院、垃圾场 |
| 地标 | 首批复用医院；后续新增警局、工厂和实验室独立大型资源 |
| 变化层 | 屋顶设备、破损、植被、车辆、箱堆、围栏、积水和路障 |

建筑资源使用“主体＋屋顶变化＋损坏覆盖＋植被覆盖＋院落小物”组合。变化层必须服从碰撞轮廓，不能只改变画面后产生看似可走但实际阻挡的区域。

### 10.3 资源生产与导入

- 先制作住宅、道路和商业三组代表资源，验证尺寸、透视、像素密度和接缝。
- 验证通过后再批量扩展同类变体。
- 资源使用透明背景或明确的地块底板，边缘必须可无缝组合。
- Cocos 导入设置沿用现有像素资源的 nearest 过滤和一致的 pixels-per-unit 规则。
- 每类资源生成资源清单，记录稳定 ID、占用格、连接点、碰撞轮廓、主题标签和允许旋转方式。

## 11. 性能预算

- 同时完整运行最多 `3×3` 个区块；`5×5` 外围只预加载纯数据和必要资源。
- 生成、实例化和回收必须分帧执行，跨区块时不得出现明显卡顿。
- 远处区块不运行逐帧 AI、动画、粒子或物理查询。
- 常见建筑、装饰、交互物和敌人表现使用对象池。
- 区块布局缓存使用明确容量上限和最近使用淘汰策略。
- 低端模式可以减少装饰密度和变化层，但不能改变道路、建筑占用、交互物、敌人数值和掉落结果。

首轮验收目标是在目标设备上连续跨越 50 个区块，内存保持稳定，帧时间没有随累计探索距离持续增长。

## 12. 错误处理

- 区块资源未及时完成：保持边界阻挡和加载提示，不允许玩家进入空白世界。
- 非关键装饰资源缺失：使用同占用尺寸的占位资源并记录错误。
- 建筑或道路关键资源缺失：该区块不激活，回退到安全基础模板。
- 变化记录引用不存在的对象：保留原记录并上报，不覆盖存档。
- 道路连接或可达性验证失败：开发构建直接失败；正式构建回退到已验证的十字安全模板。
- 异步生成结果在完成前已离开目标范围：取消实例化或立即归还，不能产生孤立节点。

## 13. 测试与验收

### 13.1 确定性

- 固定种子与坐标的布局快照保持一致。
- 区块按不同加载顺序生成时结果一致。
- 增加装饰随机抽取不改变道路、建筑和地标结果。
- 保存加载、区块回收和浮动原点平移后稳定对象 ID 不变。

### 13.2 批量生成

自动生成至少 `10,000` 个区块并验证：

- 相邻边界道路出口完全匹配。
- 每个区块至少一个出口，活动道路连通。
- 交互物、出生点和奖励不在阻挡格内。
- 住宅、商业、空地和公共设施比例处于目标区间。
- 同类稀有地标满足最小距离，整体出现率在设计范围内。
- 不存在需要无限搜索才能满足的生成步骤。

### 13.3 运行时

- 玩家跨越区块时无可见空洞、重复生成或碰撞接缝。
- 离开再返回后，宝箱、路障、探索点和持续事件状态正确恢复。
- 退出重进后相同区块与变化状态正确还原。
- 小地图随玩家滚动，已发现地标位置稳定。
- 跨区块点击移动和敌人追击可以续接路线。
- 连续探索 50 个区块后，活动节点、计时器、订阅、内存和帧时间没有随历史区块数线性增长。

### 13.4 美术

- 新住宅、商铺和道路与医院地图的视角、像素密度、光照和色板一致。
- 连续观察 20 个普通区块时，主体、破损、植被和小物组合没有明显机械重复。
- 道路和人行道跨区块无明显断线或接缝。
- 关键地标在缩略地图和世界画面中可辨认，但普通建筑仍占视觉主体。

## 14. 实施边界

首轮实施包含无限区块逻辑、流送、状态恢复、浮动原点、分层寻路、局部地图、首批住宅/道路/商业美术资源和医院地标迁移。

首轮不包含可进入建筑室内、完整昼夜区域生态模拟、多人同步、跨服务器世界共享、所有稀有地标的独立玩法、警局/工厂/实验室全部最终美术，以及无限距离全局敌群模拟。这些能力通过稳定区块键、地标定义和变化记录接口预留。
