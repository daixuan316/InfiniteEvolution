# 工坊耗时制造队列设计

## 目标

把当前仅展示静态演示数据的工坊页面改造成可玩的首章制造闭环：玩家选择配方，系统原子校验并扣除材料，将任务加入三个制造槽之一；任务在页面关闭和游戏退出后继续按真实时间推进，完成后可靠地把产物放入库存。

本阶段只实现制造与其必需的库存、队列和本地持久化，不顺带实现强化、改装、拆解、装备穿戴或完整经济系统。

## 已确认决策

- 使用三个并行制造槽，而不是即时制造。
- 队列跨页面、跨重启持续，并按真实经过时间补算离线进度。
- 新存档只发放一次首章初始材料，并提供六个内置配方，以保证当前版本可以直接体验完整流程。
- 制造开始时先完成全部校验，再一次性扣料和入队；任何校验失败都不改变库存。
- 成品默认在完成时自动入库；若存档损坏或未来系统变更导致无法入库，则任务保留为“待领取”，不丢失成品。

## 方案选择

采用“纯规则层 + 专用工坊页面 + 版本化本地仓库”。

没有采用 UI 内部直接维护计时器，因为页面生命周期不能承载跨页面、跨重启的制造状态，也难以可靠测试。没有在本次一次性补齐完整背包、装备与经济框架，因为这会把需求扩大到多个尚未落地的系统；本设计保留稳定接口，后续可让战斗掉落和装备页面复用库存。

## 引擎集成边界

项目使用 Cocos Creator 3.8.8 与 Oops Framework。

| 契约 | 项目绑定 |
|---|---|
| 页面生命周期 | `GamePage` 负责触摸绑定清理；专用 `WorkshopViewComp` 在 `start` 渲染，并在 `update` 中累计到 250 毫秒后同步一次队列和倒计时 |
| 页面装载 | `UIRuntime` 通过 `UIPageBootstrap` 将 `UIID.Workshop` 绑定到专用页面组件 |
| UI 构建 | 继续使用 `UIBuilder`、`UI_THEME` 和现有空根 prefab，不手工扩写 prefab 节点树 |
| 时间 | 规则层只接收毫秒时间戳；运行时使用当前 Unix 时间，测试注入固定时钟 |
| 状态 | 配方定义为只读内容；库存、队列和一次性初始化标记为可变存档状态 |
| 持久化 | 通过小型 `KeyValueStore` 接口隔离；Cocos 运行时绑定 `sys.localStorage`，测试使用内存实现 |
| 事件 | 使用 `GameEvent` 广播库存变化、队列变化与制造完成，UI 不直接拥有业务状态 |
| 测试入口 | 继续使用项目现有 `node --test` 与可直接导入的纯 TypeScript 模块 |

## 领域模型

### 库存

`Inventory` 按稳定物品 ID 保存数量，并提供：

- 查询数量与已用容量；
- 原子增加、移除；
- 模拟“移除配方材料后加入产物”是否可行；
- 导入和导出普通 JSON 快照。

库存容量默认 80 格。基础材料每格最多 99 个，医疗包与能源电池每格最多 10 个，武器、防具和模块每件占一格。制造入队时为产物预留容量，因此正常状态下完成任务一定能自动入库。

### 配方

`WorkshopRecipe` 至少包含：

- 稳定 ID、名称、分类和图标；
- 输入材料列表；
- 输出物品 ID 与数量；
- 制造时长；
- 解锁状态或最低工坊等级字段。

首章内置六个配方。具体材料量与耗时集中在一个只读目录中，UI 不硬编码数值。

| 配方 | 分类 | 材料 | 产物 | 耗时 |
|---|---|---|---|---:|
| 突击步枪 | 武器 | 废料 30、机械零件 20、电子元件 5 | 突击步枪 ×1 | 45 秒 |
| 霰弹枪 | 武器 | 废料 35、机械零件 25、合金 10 | 霰弹枪 ×1 | 60 秒 |
| 装甲板 | 防具 | 废料 25、合金 20 | 装甲板 ×1 | 50 秒 |
| 机枪塔模块 | 模块 | 废料 40、机械零件 30、电子元件 15、合金 15 | 机枪塔模块 ×1 | 90 秒 |
| 医疗包 | 补给 | 医疗物资 8、废料 3 | 医疗包 ×1 | 25 秒 |
| 能源电池 | 补给 | 废料 8、电子元件 6、合金 4 | 能源电池 ×1 | 30 秒 |

本阶段六个配方默认解锁；最低工坊等级字段保留在模型中，供后续内容配置使用。

### 队列

`CraftingQueue` 最多保存三个任务。每个任务包含唯一任务 ID、配方 ID、开始时间、结束时间、数量和状态：`crafting`、`ready` 或 `claimed`。

入队流程：

1. 找到配方并检查解锁条件。
2. 检查空闲制造槽。
3. 检查所有材料数量。
4. 检查扣除材料后，现有队列预留加本次产物仍能容纳。
5. 在同一领域操作中扣料并创建任务。
6. 保存完整快照；保存失败则恢复操作前快照。

同步流程以注入的当前时间为准。达到结束时间的任务尝试发放产物；成功后清除任务并释放预留，失败则保留为 `ready`。重新进入页面和应用启动时都执行一次同步，页面打开期间低频刷新显示。

## 持久化

保存键使用独立、带版本号的命名空间，例如 `infinite-evolution.workshop.v1`。快照包含：

- schema 版本；
- 库存数量；
- 三个制造槽；
- 新存档初始化标记；
- 为队列产物保留的容量信息或可从任务重建的数据。

首次没有快照时创建默认状态并发放一次初始材料。之后即使库存清空，也不会再次发放。读取到无效 JSON、未知配方或非法数量时进行保守修复：忽略非法条目、保留能识别的库存和任务，并避免重复发放初始材料。

## UI 与交互

`UIID.Workshop` 不再复用通用 `FeaturePageViewComp`，而绑定 `WorkshopViewComp`。其他功能页保持不变。

页面沿用现有三栏布局：

- 左栏：武器、防具、模块、补给四个可点击分类，并显示该分类可制作配方。
- 中栏：当前配方、产物图标、名称、耗时、材料需求以及拥有量；缺失材料使用警告色和明确数量显示。
- 右栏：三个制造槽的名称、状态、剩余时间或“待领取”，以及主操作按钮。

主按钮状态明确区分“开始制造”“材料不足”“队列已满”“配方未解锁”。失败时显示短提示且不修改状态。成功入队后立即刷新材料与队列；完成时刷新库存并派发完成事件。

## 初始内容

初始材料为废料 120、机械零件 45、合金 60、电子元件 30、医疗物资 20。它们足以制造一件基础武器、一项防御产物和一种补给，但不足以一次制造全部六种配方，保证玩家能看到材料取舍与缺口反馈。

分类映射：

- 武器：突击步枪、霰弹枪；
- 防具：装甲板；
- 模块：机枪塔模块；
- 补给：医疗包、能源电池。

所有内容使用现有 UI 图标库；若没有完全匹配的产物图标，先使用最接近的资源/制造图标，不新增美术生产范围。

## 事件与后续接入

新增：

- `InventoryChanged`：库存数量改变；
- `WorkshopQueueChanged`：任务入队、完成、领取或修复；
- `CraftCompleted`：一个制造任务完成并成功入库。

事件只携带稳定 ID 或可序列化摘要。未来战斗掉落通过同一库存服务增加材料，装备页读取同一库存快照，不再维护另一套演示资源。

## 错误处理

- 材料不足、队列已满、未解锁或容量不足：拒绝入队，状态不变，并给出可读提示。
- 本地保存失败：本次业务操作回滚并提示“保存失败，请重试”。
- 系统时间回拨：剩余时间不增加到任务原始时长之外；不会因负时间立即重复发奖。
- 重复同步：同一任务最多发奖一次，完成处理必须幂等。
- 未知配方任务：保留可识别数据并标记异常，不扣新材料、不生成未知物品。

## 测试与验收

规则层采用测试先行，至少覆盖：

- 成功入队会原子扣除材料并创建一个有结束时间的任务；
- 材料不足、队列已满、产物空间不足时库存完全不变；
- 三个槽可并行计时，第四个任务被拒绝；
- 页面关闭不影响任务，按结束时间同步可完成；
- 重启后离线时间足够时成品只发放一次；
- 新存档初始材料只发放一次；
- 保存失败会回滚扣料与入队；
- 待领取状态不会丢失产物；
- 损坏快照不会造成负数物品或重复初始化。

集成验收：进入工坊能切换分类和配方；材料数字、按钮状态与库存一致；开始制造后三个槽显示实时倒计时；返回方舟再进入进度仍在；重启预览并越过结束时间后成品存在于库存，材料没有重复扣除或发放。

## 完成标准

- 工坊不存在空按钮或静态队列演示数据。
- 六个配方均能走完选择、校验、入队、离线推进和入库流程。
- 领域规则测试、现有 UI 测试及 TypeScript 检查通过。
- 不覆盖或提交工作区中与本功能无关的用户改动。
