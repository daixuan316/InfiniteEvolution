# 宝箱双层状态素材与开启特效设计

> 日期：2026-11-10  
> 状态：已确认  
> 引擎：Cocos Creator 3.8.8 + Oops Framework  
> 画面基准：1334×750 横屏、末世工业像素插画风

## 1. 目标

为现有 16 类宝箱、资源与奖励物件补齐可直接接入游戏的双层状态素材：

- 世界场景层：待开启、开启中、已开启三种俯视物件状态。
- UI 层：待开启、开启中、已开启三种地图/交互图标状态。
- 特效层：可复用的光晕、星芒、粒子和奖励喷射素材，并由 Cocos Tween 驱动开盖、弹跳、闪烁和淡出。
- 表现接入：探索地图中的宝箱从程序占位图形升级为真实素材，并根据模拟状态切换显示。

## 2. 覆盖范围

沿用现有稳定 ID，不新增重复命名：

1. `supply-crate`
2. `armory-crate`
3. `bio-crate`
4. `heavy-safe`
5. `airdrop-crate`
6. `hidden-cache`
7. `weapon-case`
8. `medical-cabinet`
9. `scrap-pile`
10. `alloy-stack`
11. `electronics-cache`
12. `energy-cell-crate`
13. `fuel-drum`
14. `ration-box`
15. `blueprint-tube`
16. `mutation-pod`

即使部分对象不是传统翻盖宝箱，也使用同一状态语义：待搜刮、正在搜刮、已搜刮。开启中的结构变化按物件类型表达，例如柜门半开、保险柜门旋开、资源堆高亮并散落、样本舱解锁发光。

## 3. 方案选择

### 方案 A：每类独立逐帧动画

美术控制最强，但至少需要数百张图片，包体、生成成本和状态维护成本过高。

### 方案 B：单张静态图配纯程序效果

资源最轻，但无法表现柜门、箱盖和舱门的结构变化，开启反馈不够可信。

### 方案 C：三状态素材配程序动效（采用）

每类保留三个关键姿态，状态间用缩放、位移、旋转、闪光与粒子衔接。它兼顾结构变化、风格一致、包体和运行性能，适合抖音小游戏。

## 4. 资产规格

### 4.1 世界物件

- 单张尺寸：256×256 RGBA PNG，透明背景。
- 视角：与现有探索地图一致的轻度俯视/等距像素插画视角。
- 状态：`closed`、`opening`、`opened`。
- 锚点语义：视觉重心和落地点在三个状态之间保持一致，避免切换抖动。
- 轮廓：深色 2～4 像素边线，在 96～128 像素显示尺寸仍可辨认。

### 4.2 UI 图标

- 单张尺寸：128×128 RGBA PNG，透明背景。
- 状态：`closed`、`opening`、`opened`。
- 保留现有深色圆形底盘与青色描边语言；已开启状态降亮并增加明确勾选/空置结构，不能只依赖颜色。
- 在 48、64、96、128 像素下保持主轮廓可读。

### 4.3 通用特效

生成透明底的可复用贴图：

- 暖金交互光环。
- 青色科技光环。
- 洋红污染光环。
- 白金稀有星芒。
- 径向开启闪光。
- 小型方形/菱形粒子。
- 奖励向上喷射拖尾。
- 已完成柔和余辉。

特效贴图不含文字、数字、品质名称或奖励图标。品质颜色和具体奖励仍由运行时配置决定。

## 5. 生成与规范化流程

1. 使用现有世界物件和 UI 图标作为构图与风格参考。
2. 分别生成世界物件三个状态母版和 UI 图标三个状态母版；每张母版为固定 4×4、行优先顺序。
3. 生成一张通用特效母版。
4. 使用确定性脚本切片、缩放、检查透明通道并输出稳定文件名。
5. 生成机器可读清单，记录源工具、提示词、尺寸、状态、稳定 ID 和输出路径。
6. 保留母版、预览拼图和最终切片，方便后续重生成与视觉复核。

输出目录采用：

```text
assets/bundle/gui/loot-chests/
├─ world/<stable-id>/<state>.png
├─ icons/<stable-id>/<state>.png
├─ effects/<effect-id>.png
└─ asset-manifest.json

docs/design/assets/loot-chests/
├─ source-sheets/
├─ previews/
└─ prompts.md
```

## 6. 运行时设计

新增一个独立的宝箱表现资源映射模块，输入稳定类型 ID、表现层级和状态，返回对应 SpriteFrame 路径。未知 ID 或加载失败时继续使用当前程序绘制回退，避免交互对象消失。

世界对象状态流：

```text
closed → opening → opened
```

- `closed`：循环轻微呼吸光和交互光环。
- `opening`：切换中间姿态，执行 0.35～0.55 秒弹跳、闪光和粒子喷射。
- `opened`：保持结构打开/资源已取走状态，降低亮度并显示柔和余辉。

模拟层仍是权威状态来源；HUD 只读取 `discovered`、`opened` 和交互结果，不自行结算奖励。首次成功开启时播放一次 `opening`，恢复存档或节点重新进入可见范围时直接显示 `opened`，避免重复播放奖励动画。

## 7. 性能与移动端约束

- 按对象池复用世界节点与特效节点。
- 同屏开启特效设置上限，超出时保留核心闪光并减少粒子数量。
- 不为 16 类分别创建粒子材质；共用少量贴图并通过颜色、缩放和旋转变体区分。
- 使用现有 bundle 异步加载方式，并在节点不可见或被回收时取消/忽略过期回调。
- 默认不开启永久更新循环；只有呼吸光和正在播放的开启动画需要短时更新。

## 8. 验收标准

- 16 类对象均具有世界物件三状态和 UI 图标三状态，共 96 张状态切片。
- 8 张通用透明特效素材可独立叠加，无烘焙背景、文字和水印。
- 三状态切换时对象落点稳定，轮廓和配色与现有末世工业 UI 一致。
- 世界探索中四种当前可玩宝箱能够显示真实素材、播放一次开启特效并保持已开启状态。
- 隐藏宝箱在未发现时不显示，雷达揭示后显示待开启状态。
- 节点回收、离开再返回或存档恢复不会重复发奖、重复播放开启动画或显示错误状态。
- 素材加载失败时程序图形回退仍可交互。
- 自动化测试覆盖资源路径解析、状态映射和已开启对象的恢复行为；Cocos Creator 预览完成 1334×750 与较短安全区的人工复核。

## 9. 非目标

- 不修改掉落概率、奖励内容、背包规则或跨局经济。
- 不制作每类独立的长逐帧动画、音效或震动素材。
- 不在本轮把 16 类全部加入地图生成逻辑；未投放类型只完成可复用资产和映射。
- 不替换已有地图缩略图、资源物品图标和世界建筑素材。
