# 完整装备系统设计

## 目标与范围

把当前仅展示演示数据的“装备与仓库”页面改造成可持久化、可配置、真正影响战斗的完整装备系统。首批一次性交付九种武器类别、全部装备槽、仓库、三套方案、双武器、词条、标签共鸣、强化、等级同步、改装、拆解、制造、战斗记忆和二选一进化。

本功能同时补齐装备所依赖的最小存档和资源交易基础，但不扩展无关的商店、完整天赋树、任务掉落表或新美术资源。现有图标和工业科幻 UI 组件继续复用。

## 方案选择

采用“纯 TypeScript 领域规则 + Cocos 薄适配”的实现。装备规则不导入 `cc`，页面只提交命令和渲染 ViewModel，战斗只消费不可变的角色/武器快照。这样能够独立测试存档、穿脱和数值规则，并避免 UI、战斗和持久状态互相直接持有。

不采用以下方案：

- 装备全部 ECS 实体化：当前背包、角色、进化和存档模块仍是占位，立即全实体化会扩大生命周期和序列化复杂度。
- UI 直接修改战斗常量：无法可靠支持方案、存档迁移、拆解保护和战斗记忆。

## 模块边界

### 静态配置

`EquipmentCatalog` 保存只读定义：装备模板、词条、共鸣、进化路线、制造配方和首章初始内容。所有定义使用稳定 ID；运行时实例只保存定义 ID 和可变状态。

配置加载时校验重复 ID、无效槽位、缺失词条、无效进化路径、配方引用和数值边界。关键错误阻止系统初始化，避免战斗中静默降级。

### bag

`Inventory` 管理装备实例和材料堆叠；`EquipmentSet` 管理当前方案中的槽位；`LoadoutCollection` 管理三套命名方案和当前方案。

固定槽位为：`primary1`、`primary2`、`helmet`、`armor`、`gloves`、`boots`、`tactical`、`organ`。两个主武器槽只接受武器，其余槽位严格匹配类型。同一装备实例不能在同一方案中占用多个槽位，但可以被多套方案复用；任一方案引用都会提供拆解保护。方案引用缺失实例时保留空槽并返回可展示警告。

装备实例包含：实例 ID、模板 ID、等级、强化等级、品质、随机词条、标签、收藏/锁定、改装次数、已选进化路线和战斗记忆计数。装备没有耐久。

### role

`RoleEquipmentResolver` 把角色基础属性、当前方案、装备模板、词条、强化和共鸣汇总为不可变 `RoleCombatSnapshot`。快照包括生命、护盾、防御、移速、翻滚冷却，以及两把武器各自的伤害、射击间隔、射程、弹匣、换弹、过热、弹道和机制参数。

快照只在装备、方案或强化状态变化时重算。战斗开始复制快照；管理页面不能在进行中的战斗里偷偷改变当前战斗数值。

### evolve

`CombatMemory` 记录近距命中/击杀、弱点命中、连续换枪、方舟附近击杀、异常触发和高污染使用。只有史诗及以上装备会积累进化资格。

达到阈值后展示两个可预览路线；选择后写入实例并应用机制效果。路线选择不可直接覆盖，重置需要进化样本，首次与后续重置成本分开记录。

`ResonanceResolver` 按当前方案标签计数并返回已激活档位和下一档进度。首批实现雷暴、守望、机械、异化、猎荒、重装六套 2/3 件效果及代价。

### economy

`EquipmentEconomyService` 负责制造、强化、等级同步、改装和拆解。所有操作先验证实例、保护状态、资源、容量、等级上限和解锁条件，再在同一个事务中扣除与发放；失败不改变任何状态。

- 强化只提高模板基础属性，不增加词条。
- 等级不能超过角色等级和章节软上限。
- 等级同步将低级高品质装备同步到当前阶段，成本高于普通强化、低于重造同品质装备。
- 改装只替换一个指定普通词条槽，可限制词条类别，成本随改装次数递增；固定特性和进化特性不可替换。
- 拆解返还基础材料、部分强化材料，并按品质产出标签/进化样本。
- 已装备、任一方案引用、收藏、锁定、已进化以及传说/异变装备禁止批量拆解；单件高价值拆解需要二次确认。

### save

新增版本化 `CampaignSave`，持久化角色阶段、材料、装备实例、仓库、三套方案、当前方案和武器偏好。存档只保存纯数据和稳定 ID。

`SaveRepository` 采用临时键写入、校验、当前快照替换和上一有效快照保留。加载时依次尝试当前、上一快照，均无效时生成带首章装备的初始存档。迁移逐版本执行；缺失模板只移除对应引用并保留诊断信息，不清空其他进度。

## 九种武器与战斗行为

首批每类至少一个完整模板，并支持后续配置扩展：

| 类别 | 核心行为 |
|---|---|
| 突击步枪 | 中速全自动、稳定泛用 |
| 冲锋枪 | 高射速、短射程、移动输出强化 |
| 霰弹枪 | 多弹丸、近距爆发、击退和破甲 |
| 狙击枪 | 慢速单发、穿透、弱点倍率 |
| 轻机枪 | 大弹匣、持续压制、移动惩罚和长换弹 |
| 榴弹武器 | 弧线范围伤害、最小安全距离 |
| 火焰武器 | 短距持续喷射、燃烧、阻止再生、过热 |
| 电弧武器 | 连锁多个目标、感电短暂停顿 |
| 生化武器 | 感染扩散、污染增益与反噬 |

普通武器无限库存弹药，但仍执行弹匣、换弹、射击间隔和过热。战斗 HUD 提供当前武器、备选武器、弹匣/热量和换枪按钮；换枪保留各自弹匣、热量与后台换弹/散热状态。

伤害仍通过 `DamageResolver`：基础伤害 × 技能倍率 × 同类增伤池 × 暴击 × 弱点，再应用递减防御。范围、穿透、连锁、持续伤害和状态效果由武器运行时生成独立命中，不绕过统一伤害入口。

所有随机判断使用可注入、可记录的随机源。测试使用固定序列，正式战斗从战斗种子派生武器随机流。

## 词条、品质与标签

品质为普通、精良、稀有、史诗、传说、异变，决定普通词条数量和可用机制上限。词条池分为输出、操控、元素、生存和方舟联动，并声明允许的装备槽与武器类别，禁止生成无意义组合。

属性聚合顺序固定为：角色基础值 → 模板/等级 → 强化 → 固定特性 → 普通词条同类相加 → 共鸣 → 进化机制。所有百分比以小数保存，展示层负责格式化。

标签共鸣由不同装备实例贡献，同一实例的重复标签只计一次。共鸣结果同时返回当前数量、已激活效果、下一档需求和负面代价，供装备页与战斗 HUD 展示。

## 页面与交互

### 装备与仓库

为 `UIID.Equipment` 使用独立页面组件，不再读取 `FEATURE_DEMO_VIEW_MODELS`：

- 左栏：武器、防具、战术装置、进化器官分类，以及品质、标签、元素、收藏、可进化筛选。
- 中栏：八个实际装备槽、三套方案切换/重命名、双武器顺序和当前共鸣。
- 仓库区：真实装备卡片列表，展示品质、等级、强化、标签、锁定和方案占用。
- 右栏：候选与当前同槽装备的核心属性差异、词条、固定特性、进化进度和路线预览。
- 操作：装备/卸下、设为主武器、锁定、收藏、进入强化/改装/进化、单件拆解和受保护提示。

选择和操作均使用移动端点击流程，不依赖精确拖拽。任何改变成功后立即刷新 ViewModel 并提交存档；失败在原位置显示明确原因。

### 工坊

为 `UIID.Workshop` 使用独立装备工坊页面，提供制造、强化、等级同步、改装和拆解标签页。制造展示配方、缺口、产出预览和仓库空间；强化/同步/改装先展示结果与成本；拆解支持筛选和安全批量选择。

### 战斗 HUD

在现有 HUD 上增加武器状态和换枪交互，但保持移动、闪避、互动及现有地图功能不变。战斗结束或离开战斗时，把本场记忆增量合并到持久实例并保存；异常中止不重复结算同一批事件。

## 数据流

1. 启动时加载并迁移存档，创建 `BagModule`、`RoleModule`、`EvolveModule` 和装备经济服务。
2. 装备/工坊页面向模块提交命令，模块在事务副本上验证并执行。
3. 成功后生成新状态、重算角色快照、发出装备状态事件并提交存档；失败只返回错误。
4. 进入战斗时 `BattleSimulation` 接收当前角色和双武器快照，创建两份独立武器运行时。
5. 命中、击杀、换枪和状态触发产生内存中的战斗记忆事件。
6. 战斗结算将事件按装备实例 ID 汇总，解锁进化候选并持久化。

## 错误处理与兼容

- 领域命令使用明确结果类型，不用异常表示资源不足、槽位不符或受保护等预期失败。
- 非法数值、重复实例 ID、悬空方案引用和配置缺失在边界处拒绝。
- 存档提交失败时保留命令前状态并展示失败提示；不会出现材料已扣但装备未生成。
- 页面销毁时解除事件订阅，避免重复刷新和重复命令。
- 其他功能页面继续使用现有通用 `FeaturePageViewComp`，装备改造不改变它们的路由和行为。

## 测试策略

严格按测试先行实现，每个行为先看到正确原因的失败，再写最小实现：

- 单元测试：仓库容量、槽位规则、双武器、三套方案、属性聚合、词条约束、六套共鸣、强化/同步/改装/拆解事务、战斗记忆、进化选择、存档迁移和快照恢复。
- 战斗测试：九种武器的射击节奏与机制、换枪、弹匣、换弹、过热、元素状态、装备防御/生命/移速实际生效、记忆只结算一次。
- UI 集成测试：装备和工坊不再显示演示文案，关键按钮与命令绑定存在，路由和返回行为不回归。
- 回归测试：现有战斗、地图、怪物、方舟与导航测试全部通过。
- Creator 验收：打开装备页完成穿戴、切换方案、强化、改装、拆解保护和进化；进入战斗验证数值与机制变化；重启预览后状态仍在。

## 完成标准

- 装备页和工坊页所有主要按钮都有真实业务结果，不存在空回调或演示指标。
- 九种武器在战斗中具有可观察、可测试的不同机制。
- 两把主武器可独立换弹/散热并随时切换。
- 穿脱防具会改变对应战斗属性；词条、强化、共鸣和进化都进入最终快照。
- 三套方案、仓库、材料、强化、改装、拆解和战斗记忆在重启后保持一致。
- 失败交易不损失资源，受保护装备不会被批量拆解，损坏存档可回退上一快照。
- 自动化测试与类型检查通过，Cocos Creator 3.8.8 预览无新增错误。
