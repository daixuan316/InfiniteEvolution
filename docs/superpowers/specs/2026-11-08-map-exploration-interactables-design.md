# 地图探索交互与可破坏路障设计

> 日期：2026-11-08  
> 状态：设计已确认，待规格复核  
> 引擎：Cocos Creator 3.8.8 + Oops Framework

## 1. 目标

把当前医院城区从只有移动、敌人与静态兴趣点的战斗地图，补充为具备基础搜刮、调查、信息揭示和破障开路的可玩探索地图。

本轮完成以下闭环：

- 玩家能在世界中发现并接近宝箱或探索点。
- 靠近后通过统一交互按钮开启或调查。
- 交互完成后获得明确反馈，且同一对象不能重复领取。
- 雷达终端可以揭示未发现宝箱。
- 玩家在没有敌人目标时可以自动攻击可破坏路障。
- 路障摧毁后开放捷径，并同步更新碰撞、寻路和地图显示。

## 2. 范围

### 2.1 宝箱

医院城区放置四种宝箱：

| 类型 | 稳定类型 ID | 奖励倾向 | 初始可见性 |
|---|---|---|---|
| 普通物资箱 | `supply-crate` | 废料、通用材料 | 可见 |
| 医疗柜 | `medical-cabinet` | 医疗物资 | 可见 |
| 武器箱 | `weapon-case` | 弹药、武器零件 | 可见 |
| 隐藏缓存点 | `hidden-cache` | 稀有零件、情报 | 隐藏，需雷达揭示 |

点位分别服务于医院、物资仓库、信号塔和支路尽头，避免全部集中在主路。所有点位必须处于可到达位置，并与出生点、撤离点及敌人出生点保持合理距离。

### 2.2 探索点

首批加入三种一次性探索点：

| 类型 | 稳定类型 ID | 完成效果 |
|---|---|---|
| 医疗终端 | `medical-terminal` | 获得医疗补给 |
| 求救信标 | `rescue-beacon` | 获得情报并完成调查 |
| 雷达终端 | `radar-terminal` | 揭示所有尚未开启的宝箱 |

探索点使用与宝箱相同的靠近交互入口，但按钮文字和完成反馈分别为“调查”和对应结果。

### 2.3 可破坏路障

将地图中的路障从防守型结构扩展为可被玩家攻击的探索障碍。医院城区配置至少一个封锁捷径的路障：

- 存活时阻止玩家、敌人和寻路路径穿过对应阻塞单元。
- 玩家攻击范围内存在活动敌人时，敌人保持更高锁定优先级。
- 范围内无敌人时，玩家自动锁定最近的活动路障并发射现有投射物。
- 路障进入射程后显示名称、生命值和目标反馈。
- 生命值归零时进入 `destroyed` 状态，停止成为攻击目标并开放对应地图单元。
- 路障摧毁后，玩家路径和敌人路径必须能使用新开放的捷径。

现有可维修防御路障语义不再与探索路障混用。结构模型使用明确的 `breakable-barrier` 类型；维修能力不应用于已摧毁的探索路障。

## 3. 数据与组件边界

### 3.1 地图定义层

`BattleMapModel` 是地图静态布局的唯一来源，新增：

- 宝箱定义：实例 ID、类型 ID、名称、格子位置、奖励和初始发现状态。
- 探索点定义：实例 ID、类型 ID、名称、格子位置和效果。
- 可破坏路障定义：实例 ID、格子位置、阻塞单元、生命、防御和显示半径。
- 动态阻塞查询：根据路障活动状态决定单元是否可通行。

静态道路规则保持不变，动态路障只叠加阻塞或解除阻塞，不复制另一套地图。

### 3.2 模拟层

`BattleSimulation` 负责所有权威玩法状态：

- 宝箱的发现、开启和奖励结算。
- 探索点的完成和效果执行。
- 最近可交互对象查询及距离校验。
- 玩家攻击目标选择：活动敌人优先，其次为最近活动路障。
- 投射物对敌人或路障的命中与伤害。
- 路障摧毁后的动态通行刷新和寻路重算。
- 本局资源计数与一次性通知事件。

HUD 不直接修改对象状态，只调用模拟层的交互方法并读取模拟结果。

### 3.3 表现层

`BattleHUDViewComp` 负责：

- 在世界层渲染宝箱、探索点和路障。
- 显示暖黄色可交互描边、距离提示和统一交互按钮。
- 根据最近对象将按钮文字切换为“开启”或“调查”。
- 显示获得资源、调查完成、雷达揭示和路障摧毁提示。
- 在小地图和完整地图中绘制已发现但未完成的对象，以及已完成状态。
- 复用现有投射物、伤害数字和命中闪烁表现路障受击。

如果运行时素材路径不可用，物件以高辨识度程序图形回退，不能因图片加载失败导致交互不可见。

## 4. 交互流程

### 4.1 宝箱

1. 玩家进入宝箱交互半径。
2. HUD 显示宝箱名称、距离和“开启”按钮。
3. 玩家点击按钮。
4. 模拟层再次校验玩家状态、距离和宝箱未开启状态。
5. 奖励加入本局资源计数，宝箱标记为已开启。
6. HUD 显示拾取提示，世界物件和地图标记切换为完成状态。

重复点击、距离不足或玩家倒地时不发放奖励。

### 4.2 探索点

1. 玩家进入探索点交互半径。
2. HUD 显示“调查”按钮。
3. 调查成功后执行一次性效果。
4. 雷达终端将所有未开启宝箱设为已发现；其他探索点发放配置奖励。
5. 探索点标记为已完成，不能再次触发。

### 4.3 路障战斗

1. 自动攻击每次更新先选择范围内最近的活动敌人。
2. 没有敌人时，选择范围内最近的活动路障。
3. 投射物记录统一目标 ID，并在抵达时解析目标类型。
4. 命中路障时使用现有伤害结算与反馈事件。
5. 路障生命归零后立即退出目标集合、移除动态阻塞并触发路径重算。

## 5. 可见性与地图标记

- 普通宝箱进入地图时即为已发现，隐藏缓存点默认隐藏。
- 雷达终端完成后揭示所有隐藏宝箱。
- 世界中的未完成对象使用暖黄色提示；已完成对象降亮并保留轮廓。
- 小地图只显示已发现对象，使用不同图形区分宝箱、探索点和路障。
- 完整地图显示对象名称；已完成对象使用勾选或弱化样式，不能只依赖颜色。
- 被摧毁路障从危险阻塞标记切换为已开放捷径标记。

## 6. 失败处理与边界

- 交互对象数据位置若不在可通行单元，地图测试必须失败。
- 目标在点击前离开范围时，交互失败且不结算奖励。
- 玩家倒地、暂停或完整地图打开时不能交互。
- 已开启宝箱、已完成探索点和已摧毁路障不再作为有效目标。
- 投射物飞行期间目标被其他伤害摧毁时，投射物安全消失，不重复触发奖励或状态变化。
- 路障摧毁导致现有路径过期时，在下一次模拟更新中重新寻路。

## 7. 测试与验收

### 7.1 地图测试

- 所有宝箱和探索点格子可通行，并可从出生点到达。
- 路障阻塞前，捷径不能穿越；摧毁后，捷径可通行且路线缩短或发生变化。
- 所有重要格子都能正确完成世界坐标往返转换。

### 7.2 模拟测试

- 只有交互距离内且活动中的对象能成功交互。
- 宝箱奖励只结算一次。
- 探索点效果只执行一次。
- 雷达终端揭示隐藏宝箱，不自动开启宝箱。
- 敌人与路障同时在射程内时优先攻击敌人。
- 没有敌人目标时能锁定并伤害路障。
- 路障摧毁后不再被攻击，且投射物和目标状态正确清理。

### 7.3 表现测试

- 世界中可辨认宝箱、探索点和可破坏路障。
- 靠近交互对象时出现正确名称、距离和按钮文案。
- 小地图和完整地图遵守发现与完成状态。
- 开启、调查、揭示、受击和摧毁都有即时视觉或文字反馈。
- 现有移动、闪避、敌人自动攻击、投射物命中和返回方舟流程不回归。

## 8. 非目标

本轮不实现完整背包格子、随机掉落表、装备替换界面、跨局存档、跨天刷新、室内关卡、长按进度条或复杂解谜。资源以本局计数和拾取通知表达，为后续背包与存档系统预留稳定 ID 和事件边界。
