# 方舟建设完整玩法设计

## 目标

把当前仅用于展示的“方舟建设”页面改造成可持续游玩的完整闭环。玩家安装的模块必须影响供电、噪音、维修、夜间战斗和长期存档；战斗造成的模块损伤也必须回到建设页面。

## 范围

本次实现包含：

- 固定槽位与模块安装、拆卸、换位。
- 结构、能源、防御、生化四类模块及模块库存。
- 材料消耗、供电优先级、过载、噪音和相邻加成。
- 模块耐久、远程维修队列和每日维修成本上限。
- 三套布局方案及缺失模块校验。
- 活体进化、明确能力、副作用和拆除返还。
- 建设状态的版本化本地存档。
- 战斗快照、炮塔与防御设施、噪音对尸潮的影响、模块受损回写。
- 建设页和战斗页的状态反馈与自动化测试。

不新增独立游戏引擎或平行全局框架，继续使用 Cocos Creator 3.8.8、Oops Framework、现有 `GamePage`、`UIBuilder`、`GameEvent` 和纯 TypeScript 单元测试结构。

## 总体架构

采用独立方舟领域层，建设 UI、存档和战斗共同消费同一份规则。

### 内容定义

只读的模块定义包含稳定 ID、名称、分类、可安装槽位、制造费用、基础耐久、耗电、噪音、战斗能力、相邻标签和可用进化。内容定义不保存运行时数量、槽位或耐久。

首批模块覆盖完整系统：装甲板、路障、发电机、储能器、机枪塔、霰弹塔、电网、维修无人机、雷达和活体再生组织。

### 运行时状态

`ArkState` 保存：

- 存档版本和资源库存。
- 已拥有的模块实例及其稳定实例 ID。
- 七个固定槽位和当前布局。
- 三套布局方案。
- 当前供电容量、优先级和过载状态。
- 模块耐久、工作状态、维修队列和当日维修支出。
- 进化选择及对应副作用。
- 方舟核心耐久和当前噪音档位。

### 规则服务

规则保持为无 Cocos 依赖的纯 TypeScript：

- `PlacementValidator`：槽位类型、占用和布局合法性。
- `PowerAllocator`：按核心、重要、普通的稳定顺序分配能源。
- `AdjacencyResolver`：计算最多两条主要相邻关系。
- `NoiseCalculator`：计算隐蔽、可察觉、高危和诱敌四档。
- `RepairService`：报价、排队、执行维修及每日费用保护。
- `ArkEvolutionService`：校验兼容性、应用能力与副作用、拆除返还。
- `ArkService`：接收命令，原子更新 `ArkState`，重新计算派生值并发布事件。

UI 不直接写状态。安装、拆卸、换位、优先级、维修、进化和布局切换都通过 `ArkService` 命令执行。

## 建设页交互

当前 `FeaturePageViewComp` 中 `ArkBuild` 的硬编码演示分支由独立 `ArkBuildViewComp` 取代，其他功能页保持不变。

页面保留现有横屏工业 UI 框架，采用适合触控的“选择模块、选择槽位、确认操作”，不依赖精确拖放：

1. 从结构、能源、防御、生化分类选择库存模块。
2. 合法槽位高亮；非法槽位显示具体中文原因。
3. 点击槽位后预览材料消耗、总耗电、噪音、相邻加成、战斗贡献和预计停机模块。
4. 确认安装后扣除材料、更新布局并保存。
5. 已安装模块可拆卸、换位、调整供电优先级、维修和进化。

拆卸不返还制造费用，避免反复安装刷取材料。换位不产生材料费用。耐久归零的模块仍保留在槽位和库存中，但停止工作。

### 四种模式

- 结构：装甲、路障和承载设施，影响方舟耐久、保护顺序和敌人路径。
- 能源：发电、储能、优先级和短时过载；过载提高能力并增加噪音与故障风险。
- 防御：展示射程、伤害、射速、控制效果和预计战斗贡献。
- 生化：仅展示兼容模块；确认界面同时显示机制能力与量化副作用。

### 三套布局

三套布局仅保存槽位到模块实例的映射及供电优先级，不复制模块。切换前校验所需实例是否仍存在；缺失时拒绝切换并列出缺失模块。切换成功后重新计算所有派生状态并保存。

## 供电、噪音与相邻关系

供电按核心、重要、普通排序，同档使用稳定 ID 顺序，保证同一状态每次得到相同结果。供电不足的模块保持安装但进入停机状态，UI 在确认操作前列出即将停机的模块。

过载只作用于已供电且耐久大于零的模块。过载持续时间结束或能源不足时恢复标准状态。过载的额外噪音和故障风险必须进入预览。

噪音来自当前工作的发电、制造、雷达、防御、维修与广播。噪音档位影响战斗尸潮预算：

- 隐蔽：降低尸潮预算，不提供额外稀有奖励。
- 可察觉：使用标准预算。
- 高危：增加敌人和特殊感染者预算，提高结算倍率。
- 诱敌：增加高潮波与变异材料收益。

相邻加成由槽位邻接图和标签匹配产生。每个模块最多展示两条主要关系；收益和风险都进入建设预览及战斗快照。

## 耐久与维修

模块耐久状态分为完整、受损、严重受损和停机。受损状态降低效率，严重受损进一步降低效率并允许触发故障，零耐久停机但绝不永久删除。

维修消耗废料和零件。玩家选择目标、顺序与能源额度，维修无人机按队列执行。黄昏维修效率高于夜间；夜间允许远程维修，但消耗额外能源。每日维修支出受上限保护，报价和实际扣费都不能超过剩余额度。

任何资源不足、额度不足或目标已经满耐久的维修命令都原子失败，不改变资源、队列或耐久。

## 活体进化

兼容模块最多拥有一条主要进化。每个进化定义同时包含：

- 可观察的玩法能力。
- 耗电、噪音、污染、易损性或士气事件中的至少一项量化副作用。
- 建设页和战斗页可识别的视觉状态标记。

拆除进化需要确认，只返还原始变异核心价值的 50%，并精确移除该进化记录的耗电与噪音增量，不能通过重复拆装产生资源。

## 战斗集成

开战时由 `ArkState` 生成不可变 `ArkBattleSnapshot`。快照包含已供电模块、有效耐久、炮塔参数、防御设施、维修能力、噪音档位、相邻收益和进化效果。

`BattleSimulation` 使用快照生成真实战斗对象：

- 机枪塔、霰弹塔和电网作为友方设施自动选敌并造成伤害或控制。
- 装甲板和路障作为敌人可攻击的方舟防线，损坏后可能开放路径。
- 发电与储能决定战斗中的可用模块和应急能源。
- 维修无人机执行远程维修，不要求角色靠近模块。
- 雷达和生化能力改变侦测、选敌或恢复规则。
- 噪音档位调整尸潮预算、特殊感染者权重和结算倍率。

战斗期间允许应急转供、短时过载、维修队列调整和一次性应急能力，不允许重新安装或移动模块。

战斗结束后只回写允许变化的字段：模块与核心耐久、维修消耗、战利品和当日统计。建设布局和模块定义不由战斗直接修改。

## 存档

新增版本化方舟存档仓库。存档仅保存纯数据和稳定 ID，不保存 Cocos 节点、组件引用或派生缓存。

每个成功命令在派生值计算完成后原子保存。战斗中不在单次伤害结算中写完整存档，而是在安全检查点和战斗结算时写入。

加载时执行版本迁移、数值归一化和引用校验。未知模块定义被隔离并记录，其他可识别资源和模块继续加载；无法恢复的方舟布局回退到默认布局，但不清空可识别资源。

## 错误与反馈

所有用户可触发的失败返回结构化错误码和中文说明，包括：槽位类型不匹配、槽位占用、模块不存在、资源不足、供电不足、布局缺失实例、维修额度不足、进化不兼容和状态已变化。

失败命令不产生部分扣费或部分布局变化。建设页在操作前显示预测，在操作后显示实际结果；若两者因并发状态变化不一致，则拒绝旧确认并刷新预览。

## 测试与验收

纯规则测试覆盖：

- 合法与非法放置、重复占用和换位。
- 三级供电优先级、稳定排序、过载启停。
- 全部噪音档位和尸潮倍率。
- 相邻加成、收益上限和风险。
- 耐久阈值、零耐久停机、维修报价和每日上限。
- 进化兼容性、副作用、拆除返还和不可叠加。
- 三套布局保存、缺失模块拒绝和切换回滚。
- 存档往返、迁移、未知定义和损坏恢复。
- 战斗快照确定性、炮塔攻击、模块受损及战后回写。

集成测试覆盖建设页绑定、事件发布、页面重开和战斗接入。手动验收至少执行：

1. 安装一套可用防线并重启预览，布局与资源保持一致。
2. 超出供电容量，确认普通模块先停机且页面预警正确。
3. 分别进入四个噪音档位，确认尸潮预算和奖励变化。
4. 在战斗中观察炮塔攻击、路障受损、应急转供和远程维修。
5. 将模块打到零耐久，确认停机但不丢失，战后可维修恢复。
6. 保存并切换三套布局，确认缺失模块不会被自动制造。
7. 安装并拆除一次活体进化，确认能力、副作用和返还准确。

## 完成标准

建设页不再读取 `FEATURE_DEMO_VIEW_MODELS` 中的方舟硬编码数据，主界面方舟状态也改为读取真实状态。玩家安装的防御模块在战斗中可见并生效，战斗损坏能回到建设页，所有状态在重启后保持。自动化测试和 Cocos Creator 类型检查通过，现有 UI、战斗和导航回归测试不退化。
