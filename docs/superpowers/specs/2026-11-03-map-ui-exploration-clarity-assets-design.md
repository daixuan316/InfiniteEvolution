# 地图 UI 与探索辨识度素材设计

> 日期：2026-11-03  
> 状态：已确认，等待规格复核  
> 引擎：Cocos Creator 3.8.8 + Oops Framework  
> 目标平台：抖音小游戏，横屏 1334×750

## 1. 目标

解决当前区域地图、地点选择界面与实际探索战场视觉语义混淆的问题。第一批覆盖医院、警局、工厂三个地点，同时交付完整 UI 效果图和可复用独立素材。

玩家应能在一秒内分辨：

- 当前是在查看区域情报，还是已经进入可操作战场。
- 哪些地点可以点击、当前选中了哪里、点击后会发生什么。
- 进入战场后角色在哪里、能操作什么、目标和撤离方向在哪里。

## 2. 已确认交互

1. 区域地图上的地点节点只负责选中，不直接进入关卡。
2. 选中地点后展开固定详情面板，展示风险、奖励和路程。
3. 只有详情面板中的“确认出发”按钮负责加载探索关卡。
4. 探索中的完整地图只用于查看位置、路线和标记，不提供瞬移。
5. 三个地点在同一批次交付；医院先作为视觉基准，确认内部一致性后再沿用到警局和工厂。

## 3. 视觉语义

### 3.1 区域地图

- 高位区域总览，不出现玩家战斗角色、移动摇杆或技能按钮。
- 青色：已发现且可选择。
- 黄色：当前选中、推荐路线和主要确认操作。
- 洋红：感染、高风险和精英威胁。
- 灰色：未发现、未解锁或暂时不可达。
- 点击地点后，节点放大并出现黄色外框；其余节点降低亮度，但保持可辨。
- 选中后显示方舟至目标的路线、距离与预计时间。

### 3.2 地点详情

右侧详情面板固定包含：

- 地点名称与缩略图。
- 危险等级。
- 主要奖励倾向。
- 预计探索时间。
- 与方舟的距离。
- 当日特殊事件或环境风险。
- 黄色“确认出发”主按钮。

地点节点点击与“确认出发”必须使用不同反馈，避免玩家误认为选点即传送。

### 3.3 探索战场

- 镜头切换到近距离正交俯视战场。
- 必须出现玩家角色、移动摇杆、翻滚/技能/互动按钮和战场小地图。
- 场景中必须同时存在可交互物、路径分支、室内入口、任务目标和撤离方向中的至少四类。
- 可交互目标使用暖黄轮廓、地面环或悬浮标记；不可把交互信息只写进任务文字。
- 小地图只承担导航；点击可打开完整地图，但不能直接传送。

## 4. 地点差异

| 地点 | 主要资源 | 主要威胁 | 必须表现的交互 |
|---|---|---|---|
| 医院 | 医疗物资、抗污染用品 | 污染区、狭窄伏击 | 搜索救护车、净化设备、救援目标、医院入口 |
| 警局 | 武器、弹药箱、电子元件 | 装甲感染者、门禁锁区 | 门禁终端、武器库、密码线索、警局入口 |
| 工厂 | 机械零件、方舟模块材料 | 机械危险、高噪音 | 配电箱、生产线、吊机、工厂入口 |

三地共用 UI 结构、按钮位置、图标语言和颜色含义，仅替换场景、地点信息、奖励图标与环境风险。

## 5. 第一批交付物

### 5.1 完整效果图

1. 三地点可选择的区域地图总览。
2. 医院选中与详情展开状态。
3. 警局选中与详情展开状态。
4. 工厂选中与详情展开状态。
5. 医院白天探索玩法画面。
6. 警局白天探索玩法画面。
7. 工厂白天探索玩法画面。

### 5.2 独立素材

- 无 HUD 的医院、警局和工厂探索底图。
- 三个地点的方形与横向缩略图。
- 地图地点节点：默认、选中、高风险、锁定四种状态。
- 方舟位置、推荐路线、安全路线和高风险路线覆盖层。
- 污染区、锁区和高噪音区覆盖层。
- 任务、搜索、室内入口、撤离、救援、门禁、供电和危险标记。
- 医院、警局、工厂各自的关键交互物视觉素材。

完整效果图允许组合 HUD 和示意文字；独立场景与交互素材不得烘焙 HUD、路线、标签、角色或敌人。

## 6. 技术规格与目录

输出目录：

```text
docs/design/assets/map-ui-v2/
├─ mockups/
├─ maps/
├─ location-thumbnails/
│  ├─ square/
│  └─ wide/
├─ map-nodes/
├─ route-overlays/
├─ hazard-overlays/
├─ markers/
├─ interactables/
└─ asset-manifest.json
```

- 完整 UI 与场景底图：1334×750 PNG。
- 方形地点缩略图：512×512 PNG。
- 横向地点缩略图：512×288 PNG。
- 地图节点与标记：透明 RGBA，按 128×128 母版生成并验证缩小到 64/96 px 后的辨识度。
- 场景交互物：透明 RGBA，保持正交高位俯视角和现有像素密度。
- 不覆盖现有 `world-characters-monsters` 和 `ui-mockups` 资产。
- 正式 UI 文本和数值最终由 Cocos 组件绘制；效果图中的文字只用于说明布局。

## 7. 生产顺序

1. 以现有灰港区域图、世界地图 UI、医院街区和主玩法效果图为参考生成医院完整样板。
2. 在医院样板中验证区域地图与探索战场的辨识差异。
3. 锁定布局、颜色、描边、像素密度和标记尺寸。
4. 沿用相同视觉规则生产警局和工厂。
5. 拆分并规范化独立素材，生成预览表和机器清单。
6. 在 1334×750 原生尺寸，以及图标 64/96/128 px 三档检查可读性。

## 8. 验收标准

- 不看说明文字也能通过是否出现角色、摇杆和技能区分区域地图与探索战场。
- 地点默认、选中、高风险和锁定状态不能只依靠颜色区分，还应具有轮廓或符号差异。
- 玩家能在两次点击内完成“选择地点 → 确认出发”。
- 地点详情中的危险、主要奖励和距离能在三秒内被识别。
- 三个地点的 UI 结构完全一致，场景和互动身份明显不同。
- 每张探索效果图至少展示四类场景互动或导航信息。
- 独立素材尺寸、Alpha、命名和目录通过自动检查。
- 素材在实际游戏尺寸下轮廓清晰，不依赖效果图放大观看。

## 9. 范围边界

本批不制作方舟主界面、方舟布局、夜间防守、室内完整关卡、角色动画或实际 Cocos 交互逻辑。它们可以复用本批建立的地图节点和标记规范，但不进入当前素材批次。
