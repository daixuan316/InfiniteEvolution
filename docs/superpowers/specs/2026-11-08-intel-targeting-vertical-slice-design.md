# 情报目标与探索引导纵向闭环设计

- **日期：** 2026-11-08
- **项目：** 无限进化·末世生存
- **引擎：** Cocos Creator 3.8.8、TypeScript、Oops Framework
- **状态：** 已确认，可进入实现计划

## 1. 目标与范围

把当前只有静态占位内容的“地图与情报”页改造成真实影响探索流程的功能：玩家必须先从情报页选择目标，大厅才能发起探索；进入医院城区后，目标名称、距离、地图高亮和抵达反馈都与选择一致。

本次包含：

- 独立情报页及“地图、任务、事件、尸潮”四个可切换标签。
- 战地医院、物资仓库、信号塔三个现有地点的情报定义。
- 地点风险、距离、预计耗时、奖励倾向和目标任务展示。
- 当前会话内的目标选择状态。
- 大厅出发前置校验、目标摘要和情报页引导。
- 战斗页目标文案、距离、迷你地图/全地图高亮和抵达反馈。
- 纯规则单元测试、页面绑定测试和战斗接入回归。

本次不包含：跨启动存档、每日随机刷新、情报货币消耗、完整任务结算、动态尸潮导演、多张可切换战斗地图或新地图美术。事件和尸潮标签使用首个可玩切片的配置情报，后续可替换为世界状态和尸潮导演输出。

## 2. 现状与根因

当前 `UIID.Intel` 注册到通用 `FeaturePageViewComp`。该页面从 `FEATURE_DEMO_VIEW_MODELS` 读取固定文本，分类按钮没有触摸行为，“设为目标”按钮绑定空函数。大厅的“出发探索”直接打开 `BattleHUD`，战斗页则始终显示“搜索医院物资并撤离”。

因此情报页既不拥有运行时状态，也不向大厅或战斗传递目标；现有问题不是缺少按钮反馈，而是缺少完整的数据流。

工程已有可复用基础：

- `BattleMapModel.createHospitalDistrictMap()` 定义了战地医院、物资仓库、信号塔和方舟撤离点。
- 同一地图已经包含医疗终端、求救信标、雷达终端、隐藏缓存点和对应奖励。
- `BattleHUDViewComp` 已有日钟、目标栏、距离标签、迷你地图与全地图绘制。
- `UINavigationService` 支持页面参数，`GameEvent` 和 Oops 消息用于模块间低频通知。

## 3. 方案选择

采用“纯情报目录与会话状态 + 独立情报页面 + 战斗目标适配”的纵向闭环。

不采用仅补 UI 点击的方案，因为选择结果仍然不会影响探索；也不在本次提前实现完整世界任务、随机事件和尸潮导演，因为这些系统尚未完成，扩大范围会产生第二套临时规则。

本方案直接复用医院城区的真实地点与探索对象。情报定义负责把地图数据转成玩家可读信息，会话状态只保存当前目标，UI 只提交选择和渲染结果，战斗页只消费已验证的目标定义。

## 4. 情报领域模型

### 4.1 目标定义

`IntelTargetDefinition` 至少包含：

- 稳定 `id`，与 `BattleMapModel.pointsOfInterest` 的地点 ID 一致。
- 地点名称、目标标题和简短说明。
- 风险等级：`low | medium | high`。
- 奖励倾向数组。
- 预计行动时间。
- 地图格坐标。
- 关联的探索点或战利品 ID，用于说明现场可获得内容，不重复发放奖励。

首版目标：

| ID | 地点 | 目标 | 风险 | 奖励倾向 |
|---|---|---|---|---|
| `hospital` | 战地医院 | 搜索医疗补给 | 中 | 医疗物资、医疗终端 |
| `depot` | 物资仓库 | 回收建造材料 | 高 | 废料、零件、补给箱 |
| `signal` | 信号塔 | 调查异常信号 | 高 | 弹药、零件、情报 |

距离由地图起点和目标格坐标计算，显示层统一转换为米。预计耗时使用明确配置，避免把 UI 文案与路径算法耦合。

### 4.2 任务、事件与尸潮情报

- “任务”标签按目标定义生成三张任务卡，可从任务卡选择同一目标。
- “事件”标签展示求救信标、雷达终端和隐藏缓存点。已知设施显示地点与效果；隐藏缓存点标为“待雷达侦测”，不提前暴露其具体位置。
- “尸潮”标签展示首个可玩切片的次夜威胁等级、预计敌人和整备建议。数据放在情报目录中，不从 `UIDemoData` 读取。
- 事件和尸潮标签首版只读，不伪造尚未存在的领取、派遣或反制按钮。

### 4.3 会话状态

`IntelRuntime` 是无 Cocos 依赖的纯 TypeScript 状态对象，持有 `selectedTargetId`，并提供：

- `selectTarget(id)`：只接受目录中存在的目标。
- `selectedTarget`：返回完整目标定义或 `null`。
- `clear()`：为新章节或测试重置。

应用运行期间共享一个明确命名的 `intelRuntime` 实例。它不负责存档、奖励、任务完成或页面导航，避免成为通用全局状态容器。以后接入存档时只序列化稳定目标 ID。

## 5. 情报页交互

`UIID.Intel` 改为注册独立 `IntelPageViewComp`，其他功能页继续使用 `FeaturePageViewComp`。

页面保持现有科幻框架和三栏结构，但中间区域不再显示通用插槽：

- 左栏四个标签都可触摸，当前标签有明确选中态。
- “地图”显示地点节点或地点卡；点击后更新选中目标和右侧详情。
- “任务”显示三个与地点关联的任务；点击任务等价于选择其地点目标。
- “事件”和“尸潮”展示对应情报卡，右侧显示所选情报详情，不改变探索目标。
- 右栏在地图/任务标签显示风险、距离、耗时、奖励和“设为目标”。
- 未选择地点时主按钮禁用并提示先选择目标。
- 点击“设为目标”写入 `intelRuntime`，发出低频 `IntelTargetChanged` 事件并返回大厅。

标签切换、卡片选择和设定目标都使用同一轮渲染状态；重新渲染前清理旧内容节点，避免重复监听或叠加节点。

## 6. 大厅与导航

大厅中央区域增加当前探索目标摘要；未选择时显示“尚未选择探索目标”，已选择时显示地点、风险和奖励倾向。

点击“出发探索”时：

1. 读取 `intelRuntime.selectedTarget`。
2. 若为空，显示提示“请先在情报中选择探索目标”，随后打开 `UIID.Intel`。
3. 若存在，使用 `uiNavigation.replace(UIID.BattleHUD, { targetId })` 打开战斗页。
4. 页面成功打开后再派发 `GameEvent.EnterBattle`。

情报页设定目标后返回大厅时，大厅重新渲染并展示新目标。其他功能页往返不会清除选择；从战斗返回大厅也保留当前目标，方便重试。新章节重置逻辑以后显式调用 `intelRuntime.clear()`。

## 7. 战斗目标接入

`BattleHUDViewComp` 在加载时读取页面参数 `targetId`，通过情报目录解析目标。大厅保证正常流程一定携带有效目标；为开发直开战斗页和旧测试保留安全回退，缺失或非法 ID 使用 `hospital`，但不会写回用户选择。

战斗表现：

- 底部目标栏显示对应任务标题和地点名称。
- 右上距离标签优先显示目标距离，格式为“目标 123m”；抵达后显示“已抵达”。
- 迷你地图和全地图使用橙色高亮目标标记，方舟撤离点继续保持原有语义色。
- 全地图打开时仍按现有规则降低时间倍率，不改变暂停语义。
- 玩家与目标世界坐标的距离进入目标半径后，状态从 `tracking` 变为 `arrived`，显示一次明确抵达反馈，并派发 `IntelTargetReached`。
- 抵达只代表到达目标区域，不自动发放奖励，也不代替已有箱子、终端和信标交互。

目标状态转换只发生一次，避免每帧重复派发事件或重复提示。

## 8. 事件与数据流

```text
情报目录 ──> IntelPageViewComp ──select──> IntelRuntime
                                           │
                                           ├──> HallViewComp 出发校验与摘要
                                           │
                                           └──targetId──> BattleHUDViewComp
                                                           │
                                                           └──抵达事件/反馈
```

新增低频事件：

- `IntelTargetChanged`：目标选择完成，供当前可见大厅或以后其他摘要 UI 刷新。
- `IntelTargetReached`：首次进入目标区域，供提示、音效和以后任务系统消费。

逐帧距离不通过全局事件广播；它只在战斗页内部计算和渲染。

## 9. 错误处理与不变量

- 目录中的每个目标 ID 必须唯一，并对应医院地图中一个现有可通行地点。
- 会话状态不得保存未知目标 ID。
- 大厅不得在无目标时进入战斗。
- 战斗页对缺失或非法参数采用医院目标作为开发兼容回退，不能崩溃。
- 抵达事件对一次战斗中的同一目标最多派发一次。
- 隐藏缓存点在事件页不得泄露具体坐标。
- 目标抵达不得直接修改奖励或探索对象状态。
- 情报页销毁或重渲染后不得残留重复触摸与消息监听。

## 11. 测试策略

所有生产逻辑遵循失败测试先行。

### 11.1 纯规则测试

- 目录目标 ID 唯一，并与医院地图地点一一对应。
- 风险、奖励、预计耗时和坐标完整。
- 选择合法目标成功，选择未知目标被拒绝且不覆盖旧选择。
- 清理会话状态后不再存在已选目标。
- 目标距离和抵达判定覆盖边界值。

### 11.2 UI 与集成测试

- `UIID.Intel` 注册 `IntelPageViewComp`，其他五个功能页仍注册通用页面。
- 四个标签、地点卡、任务卡和主按钮存在真实绑定。
- 大厅出发读取目标并把 `targetId` 传给 `BattleHUD`。
- 无目标时大厅打开情报页而不是战斗页。
- 战斗页读取目标、更新目标文案、绘制高亮并只触发一次抵达事件。
- 现有导航、暂停、日钟、战斗模拟和 UI 组合测试继续通过。

### 11.3 手动验收

1. 启动到大厅，不选择目标直接点击“出发探索”；应提示并进入情报页。
2. 在地图标签选择“物资仓库”，核对风险、距离、耗时和奖励，然后设为目标。
3. 返回大厅，确认目标摘要变为“物资仓库”。
4. 点击出发，确认目标栏、距离和地图高亮都指向物资仓库。
5. 抵达仓库，确认只出现一次抵达反馈，现场箱子奖励仍由既有交互结算。
6. 返回大厅，切换到信号塔任务并再次出发，确认目标完整切换。
7. 检查事件页不会暴露隐藏缓存坐标，尸潮页没有伪造可执行按钮。

## 12. 完成标准

- 情报四个标签均能切换并展示对应真实内容。
- 玩家可以从地图或任务标签选择目标并返回大厅。
- 未选择目标无法从大厅出发。
- 已选目标真实改变战斗 HUD、目标距离和地图标记。
- 抵达目标区域产生一次性反馈，但不重复或越权发放奖励。
- 自动测试通过，Cocos Creator 中完成至少两种目标的端到端手动验收。
