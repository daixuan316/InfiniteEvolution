# Hall 主界面视觉替换设计

日期：2026-11-04  
目标引擎：Cocos Creator 3.8.8  
设计分辨率：1334×750 横屏

## 目标

把当前以程序描边和纯色块为主的 Hall 主界面替换为可实际交互的像素末日工业 UI。保留现有信息层级、七个入口和导航逻辑，解决背景、面板、按钮及图标素材未正确呈现的问题。

## 方案比较

1. **复用现有素材并补齐 Hall 专属装饰（采用）**：继续使用 `ark-garage`、`ark-base`、P0 通用组件和已有图标，新增少量 Hall 专属框体/装饰。风格一致、接入风险最低，也便于后续迭代。
2. **生成整张主界面底图**：出图速度快，但文字、按钮和状态区域会烘焙进背景，不利于交互、适配和数据更新。
3. **全部改为程序绘制**：适配最稳定，但像素质感较弱，无法满足“补充 UI 素材显示”的目标。

## 视觉设计

- 基调：像素末日工业、深海军蓝底、青色能量线、橙色警戒点缀、少量洋红色威胁提示。
- 背景：方舟车库场景全屏铺设，覆盖轻度暗角遮罩，保证文字可读。
- 顶栏：金属长条框，左侧章节与昼夜阶段，右侧废料、合金、能源三项资源；图标与数字分层渲染。
- 左栏：方舟状态面板，显示核心耐久、能源负载和模块槽位；进度条使用独立填充，不在图片中烘焙数值。
- 中央：弱遮罩展示方舟主体，不再用大块纯色面板完全遮挡场景；标题和出发提示保持轻量。
- 右栏：次夜尸潮面板，使用洋红/红色威胁层级和倒计时，突出与普通状态的区分。
- 底栏：六个功能按钮采用统一金属底板和图标；“出发探索”使用橙色主按钮，形成唯一主行动。
- 所有文字、数字、图标和动态进度继续由 Cocos 节点渲染，素材只负责框体和装饰。

## 组件与资源边界

- `HallViewComp` 负责 Hall 布局、信息组织和交互绑定。
- `UIBuilder` 负责 SpriteFrame/Texture 加载、九宫格面板、图标和降级绘制；资源加载失败时保留可用的程序绘制底板。
- Hall 专属素材放在 `assets/bundle/gui/hall/texture/`，通用组件继续放在 `assets/bundle/gui/ui-p0/texture/common/`。
- 不改动导航栈、页面 ID、演示数据结构和其他功能页。

## 数据与交互

Hall 加载时先同步创建可交互节点，再异步挂载纹理。纹理返回后只更新对应 Sprite，不重建按钮或重复绑定事件。六个功能入口继续调用 `uiNavigation.push()`；出发按钮继续调用 `replace(UIID.BattleHUD)` 并在成功后派发 `EnterBattle`。

## 适配与异常处理

- 关键控件维持在安全区，支持 1334×750、1600×900、1800×900 和 1950×900。
- 面板和按钮使用九宫格；像素插画保持等比缩放，避免拉伸方舟主体。
- 纹理加载失败时销毁空 Sprite 节点并保留程序描边底板，控制台不产生未处理异常。
- 不覆盖当前工作区中与本次视觉替换无关的修改。

## 验收标准

- Hall 首屏能看到车库背景、方舟主体、顶栏资源图标、左右状态框和底部按钮纹理。
- 界面不再出现大面积空白纯色面板；文字与背景对比清晰。
- 七个入口可点击，导航行为与当前实现一致。
- `npm run test:ui` 全部通过。
- Cocos Creator 预览无资源加载红错，并保存一张 1334×750 的最终效果截图作为验收记录。
