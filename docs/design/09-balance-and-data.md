# 09｜数值、配置与内容生产规范

## 1. 原则

- 数值服务机制，不用数值掩盖内容不足。
- 同一阶段的武器保持不同优势，不追求所有场景同等效率。
- 成长曲线可预测，随机性主要改变构筑而非决定能否继续。
- 所有可调参数进入配置，不散落在表现脚本中。
- 配置使用稳定 ID，并经过自动校验。

## 2. 战斗基线

| 目标 | 同阶段合理构筑的推荐击杀时间 |
|---|---:|
| 普通行尸 | 0.5–1.5 秒 |
| 奔袭者、喷吐者 | 2–4 秒 |
| 巨躯者 | 6–10 秒 |
| 普通精英 | 15–25 秒 |
| BOSS 单阶段 | 60–120 秒 |

角色受到同阶段普通怪连续攻击时，应留出反应、翻滚或治疗窗口。单次未预警攻击不能直接从满生命击倒角色。

## 3. 伤害与防御

推荐逻辑：

最终伤害 = 基础伤害 × 技能倍率 × 同类增伤池 × 暴击或弱点 × 元素与状态修正 × 防御修正。

规则：

- 同类增伤相加，独立机制才进入独立乘区。
- 暴击率、减伤、冷却缩减设置硬上限。
- 防御采用递减收益。
- 弱点命中必须依赖位置、时机或状态，不是免费永久加成。
- BOSS 对控制采用失衡值，不完全免疫。

## 4. 成长曲线

- 角色基础属性增长保持平缓。
- 装备等级提供稳定底线，品质与特性提供玩法差异。
- 每章敌人基础强度提升与玩家可获得提升大致匹配。
- 新章节的主要难度来自环境和敌人组合。
- 回到旧章节时可使用高威胁重访版本，避免普通版本变成高收益无风险刷取。

## 5. 资源基线

普通探索成功的预期净收益：

- 足以支付基础维修。
- 足以进行一次小型强化或积累关键升级的 25%–40%。
- 至少获得一个可见的长期推进：蓝图进度、任务、捷径、材料或装备。

高风险探索成功应比普通路线多提供一个机制级回报，例如稀有蓝图、完整装备、方舟模块或 BOSS 情报，而不只是更多金币。

## 6. 掉落结构

掉落表分层：

1. 必掉：金币、主题基础材料。
2. 权重掉落：装备、稀有材料。
3. 首次掉落：蓝图、档案、独特物。
4. 保底计数：连续未获得目标类型时逐步提高概率。
5. 条件掉落：高噪、无伤、清巢等挑战奖励。

保底计数保存在存档中。读档、重试和退出不能重置保底。

## 7. 尸潮预算

威胁预算由基础天数预算乘以章节、噪音、事件和区域修正。动态表现修正只在有限区间内影响下一晚。

预算项包括普通怪、特殊怪、精英、方向切换、环境事件和持续时间。每项设置最小与最大占比，避免预算全部生成单一高威胁单位。

## 8. 配置表

建议配置域：

| 配置 | 关键字段 |
|---|---|
| Item | ID、类型、堆叠、品质、图标、标签 |
| Weapon | 模板、伤害、射速、弹匣、换弹、射程、热量 |
| Affix | 适用槽位、数值区间、分组、互斥 |
| Evolution | 条件、路线、效果、副作用、外观 |
| ArkModule | 槽位、耐久、耗电、噪音、功能、升级 |
| Monster | 职能、属性、行为、弱点、掉落 |
| Horde | 预算、波次、单位池、事件、上下限 |
| Location | 地点、资源、敌人、事件、路线 |
| Quest | 前置、目标、奖励、失败规则 |
| Survivor | 岗位、特质、缺陷、任务、立场 |
| ChapterDay | 天数、天气、教学、事件、夜晚 |
| AudioCue | 事件、总线、变体、冷却、优先级 |
| UIString | 文本 ID、中文、英文、上下文 |

## 9. 稳定 ID

建议前缀：

- item_
- weapon_
- affix_
- evo_
- ark_
- monster_
- horde_
- location_
- quest_
- survivor_
- chapter_
- audio_
- ui_

ID 一经进入正式存档不得复用。删除内容时保留迁移映射或废弃记录。

## 10. 内容模板

### 新武器验收字段

- 战斗角色和目标场景。
- 基础节奏与操控参数。
- 固定特性。
- 适用词条池。
- 两条进化路线。
- 标签与元素。
- 音效、动画、特效和图标需求。
- 同阶段对照武器和差异。

### 新怪物验收字段

- 主要职能。
- 目标优先级。
- 预警方式。
- 弱点与角色反制。
- 方舟反制。
- 动画和音效状态。
- 尸潮预算成本。
- 掉落和章节首次出现。

### 新地点验收字段

- 地标和路线。
- 主要资源。
- 常见敌人。
- 特殊互动。
- 动态状态。
- 日落返程距离。
- 一项永久改变。

## 11. 配置校验

构建前自动检查：

- ID 唯一且引用存在。
- 掉落权重有效。
- 配方材料和产出存在。
- 词条适用范围不为空。
- 章节必需蓝图有保底来源。
- 任务前置不存在闭环。
- BOSS 核心数量满足科技树要求。
- 本地化键完整。
- 音频和图标引用存在。

## 12. 平衡测试

- 固定种子重放同一昼夜，对比不同构筑。
- 记录伤害来源、承伤、维修、资源净收益和死亡原因。
- 分别测试低构筑、中位构筑和目标上限构筑。
- 先调整机制成本，再调整纯数值。
- 每次改动记录受影响章节、装备和敌人，不进行无记录的全局倍率修改。

## 13. 验收

- 配置可表达首章所有内容而无需为单个物品硬编码。
- 所有主线必需内容有保底。
- 同阶段至少三种构筑可以通关。
- 资源负循环存在恢复路径。
- 新内容加入时能通过模板和校验发现缺项。
