# 10｜技术架构、存档与性能

## 1. 技术基线

- Cocos Creator 3.8.8。
- TypeScript。
- Oops Framework。
- 横屏参考分辨率 1334×750。
- 目标平台优先抖音小游戏。

保持现有框架约定，通过配置、事件和模块边界扩展，不引入平行的全局单例体系。

## 2. 模块边界

| 模块 | 职责 |
|---|---|
| initialize | 启动、公共资源、配置和存档加载 |
| hall | 主界面、继续游戏、档案入口 |
| battle | 昼夜阶段、伤害、波次、结算 |
| role | 角色状态、移动、技能、装备效果 |
| world | 章节地图、地点、动态状态、撤离 |
| bag | 物品实例、堆叠、装备槽、仓库 |
| evolve | 天赋、装备记忆、模块进化、共鸣 |
| shelter | 方舟布局、耐久、供电、噪音、维修 |
| monster | 怪物定义、AI、精英和 BOSS |
| survivor | 幸存者、岗位、士气、任务 |
| economy | 制造、强化、改装、拆解、交易 |
| save | 版本化状态、快照、迁移与恢复 |
| account | 平台登录和云能力预留 |

模块通过 GameEvent 或明确服务接口交换结果。UI 不直接修改存档对象，战斗实体不直接写磁盘。

## 3. 数据分层

### 静态定义

武器模板、怪物、词条、任务、章节、模块和音频提示。由配置加载，只读共享。

### 运行时实例

装备实例、角色状态、模块耐久、敌人状态和当天掉落。拥有生命周期，不直接复用静态定义对象。

### 持久状态

角色成长、装备实例、方舟、世界变化、幸存者和图鉴。使用可序列化纯数据与稳定 ID。

### 表现状态

动画、粒子、节点引用、临时补间和音频播放。绝不写入存档。

## 4. 事件流

典型流程：

1. 战斗系统结算伤害。
2. 角色或怪物状态更新。
3. 发出状态变化事件。
4. HUD 订阅事件并刷新。
5. 结算系统在阶段结束时汇总持久变化。
6. 保存系统写入快照。

HUD 不在每帧主动读取完整角色和方舟状态。高频数据如倒计时可由单一计时源驱动，避免多个界面各自计时。

## 5. 场景与生命周期

- Main 负责框架启动。
- Hall 作为长期管理界面。
- World/Battle 场景或预制体负责当前昼夜玩法。
- 切换阶段时先停止生成、输入和计时，再回收实体与特效。
- 对象池在章节切换或内存压力时允许清理。
- 事件订阅在模块卸载时解除，避免重复回调。

## 6. 存档结构

存档至少包含：

- schemaVersion。
- 当前章节、天数、阶段和随机种子。
- 角色等级、天赋、技能、生命、伤势、污染。
- 装备实例、词条、强化、进化和记忆计数。
- 背包、仓库、货币和材料。
- 方舟模块、布局、耐久、供电方案和进化。
- 地图捷径、尸巢、设施、事件和 BOSS 削弱。
- 幸存者、岗位、士气、任务和伤势。
- 图鉴、剧情选择、结局条件和设置。

所有引用通过稳定 ID 和实例 ID 保存，不保存节点、组件或内存地址。

## 7. 快照

- profile：长期设置、图鉴和已解锁内容。
- campaign：当前主线长期状态。
- dayStart：白天出发前状态。
- duskRetry：夜战确认前的重试状态。
- recovery：后台或异常退出的轻量恢复点。

写入新快照后校验成功，再替换旧快照。始终保留上一份有效版本。

## 8. 迁移

每次存档结构变化增加 schemaVersion。迁移按版本逐级执行：

1. 读取旧版本。
2. 复制到临时对象。
3. 逐级迁移字段和废弃 ID。
4. 校验必要字段和引用。
5. 写入新快照。
6. 保留旧备份直到新存档成功加载一次。

不能通过清空存档处理正式版本升级。

## 9. 随机性

- 章节、掉落、事件和尸潮使用可记录种子。
- 不同系统使用派生随机流，避免某个额外抽取改变全部后续结果。
- duskRetry 重试默认使用相同核心波次种子，防止通过反复重开刷新简单尸潮。
- 保底计数和关键掉落结果属于持久状态。

## 10. 性能预算

### 帧率

- 标准模式目标 60 FPS。
- 低端模式目标稳定 30 FPS。
- 核心输入与角色移动更新优先级最高。

### 同屏对象

- 普通敌人采用对象池和分级更新。
- 远处或被遮挡敌人降低决策频率。
- 大量同类敌人共享路径或流向。
- 掉落物、尸体、伤害数字和粒子设置硬上限。

### 图形

- 控制透明叠加和超大纹理。
- 背景分层按章节加载。
- 图集按 UI、角色、怪物和章节拆分，避免加载无关资源。
- 低端模式减少粒子、视差、尸体停留和动态光效果。

### 音频

- 限制同类枪声和命中音复音数。
- 长音乐和环境音使用适合平台的流式或分段策略。
- 音频对象池化，结束后归还。

## 11. 错误处理

- 配置加载失败：阻止进入游戏并显示具体配置域。
- 非关键资源加载失败：使用明确的占位资源并上报。
- 存档校验失败：尝试上一快照，不覆盖损坏文件。
- 网络或平台接口失败：允许本地游戏继续，延后同步。
- 战斗关键实体缺失：安全结束当前阶段并回到 duskRetry，而不是继续产生错误状态。

## 12. 日志与诊断

开发构建记录：

- 阶段切换。
- 随机种子。
- 伤害和死亡原因汇总。
- 尸潮预算与生成结果。
- 资源收入与支出。
- 存档写入、迁移和恢复。
- 峰值同屏对象、帧时间和内存。

正式构建关闭逐帧详细日志，仅保留错误和关键摘要。

## 13. 自动测试重点

- 物品增加、移除、堆叠和满背包。
- 制造原子性。
- 装备穿脱、共鸣和进化。
- 伤害、异常和防御边界。
- 方舟供电优先级。
- 任务图可达性。
- 掉落保底。
- 存档往返和版本迁移。
- duskRetry 重试一致性。
- 配置引用完整性。

## 14. 技术验收

- 模块职责没有形成新的全局万能管理器。
- UI 通过事件更新主要状态。
- 场景切换后不存在重复事件订阅。
- 存档损坏时可恢复上一有效快照。
- 低端模式不改变玩法数值。
- 首章完整流程在目标平台满足帧率和内存预算。
